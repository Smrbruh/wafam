# Qadam — Астана начинается с одного шага

Рабочий прототип для задачи №1 «ИИ-помощник по прогулкам в городе Астана», Build with AI.

## Запуск за минуту

Нужен Node.js 22 или новее. Зависимости устанавливать не нужно.

```sh
npm start
```

Откройте http://localhost:4173. Не открывайте dist/index.html через file://: браузеру нужен HTTP-сервер для загрузки базы.

## Настоящая генерация Gemini (опционально)

Скопируйте `.env.example` в `.env`, вставьте свой ключ в `GEMINI_API_KEY`, затем перезапустите `npm start`. Поле `GEMINI_MODEL` позволяет выбрать доступную вашей учётной записи модель. Ключ читается только локальным Node-сервером. Не публикуйте `.env`, не вставляйте ключ в интерфейс или чат. Файл исключён из Git и архива.

При доступном ключе браузер передаёт серверу запрос и идентификаторы найденных мест. Сервер повторно читает доверенную базу, выбирает только эти записи и отправляет их Gemini. Координаты пользователя не входят в запрос к модели. Введённый текст сам может содержать адрес или личные сведения — не вводите их без необходимости. Модель не выбирает произвольные места вне retrieved context. Её текст показывается как совет Gemini отдельно от карточек и не используется как проверенные часы/навигация.

Без ключа, при сбое или лимите API остаётся рабочий локальный режим: TF-IDF retrieval + объяснения по шаблонам. **Это не LLM-генерация.** Публично не заявляйте успешный вызов Gemini, пока не проверили его со своим ключом. Использование Gemini может тарифицироваться провайдером.

Развёрнутый Sites preview статический: интерфейс, POI, retrieval, карта и маршруты работают; `/api/generate` доступен только в локальном Node-сервере. Новая публикация Sites приватна для владельца, она не является общедоступной ссылкой для жюри. Для сдачи используйте архив либо отдельно настройте разрешённый доступ.

## Возможности

- Пять стартовых районов и добровольная геолокация, округлённая до 0,001°.
- Время 30–180 минут, радиус 1/3/5 км, категории, помещения, вечер и строгая доступность.
- 1–3 рекомендации: «почему», идея действия, время, исходная запись OSM и неизвестные часы.
- Интерактивная карта, мини-маршрут с общим бюджетом, выгрузка плана и переход в Google Maps.
- Раскрываемая панель поиска с оценками и исключёнными кандидатами.
- Работа retrieval без внешнего LLM; подключение Gemini на сервере при наличии ключа.

## Данные и автоматический сбор

В комплекте **186 реальных POI**, собранных из OpenStreetMap 19 октября 2026 (UTC): 123 кафе, 35 ориентиров, 14 парков, 7 торговых центров, 6 музеев, 1 именованная площадка. Это ограниченная выборка районов, не каталог всех мест Астаны. Категория кафе может включать близкие объекты питания по исходным тегам.

```sh
node scripts/collect-pois.mjs --map
```

Без `--map` скрипт сначала пробует Overpass, затем официальный OSM map API. При первоначальном сборе Overpass не ответил, fallback успешно получил 16 участков. Сохраняются теги, источники, время получения, null для неизвестных полей; повторы объединяются. `dist/data/collection-report.json` описывает результат. Фактические числа могут измениться при обновлении.

Данные: © OpenStreetMap contributors, ODbL 1.0: https://www.openstreetmap.org/copyright. Сбор — https://wiki.openstreetmap.org/wiki/Overpass_API и https://wiki.openstreetmap.org/wiki/API_v0.6. Карта использует тайлы OSM; библиотека Leaflet 1.9.4 включена локально (BSD-2-Clause). Шрифт Manrope запрашивается Google Fonts; без сети используется системный шрифт. Неизвестные доступность, розетки, тишина, рейтинг и события не додумываются.

Важный пример свежести: бывшая сфера «Нур Алем» в текущем OSM названа Alem.ai с `museum=future`; приложение не обещает работающий музей в этом здании.

## RAG и ранжирование

1. Автоматический сбор POI → нормализация → дедупликация → JSON snapshot с provenance.
2. Haversine геофильтр → оценка пешком → посещение → жёсткие фильтры.
3. TF-IDF по имени/описанию/тегам, словарь русских намерений и бонус близости.
4. Три релевантных записи → шаблонные объяснения или optional Gemini с ограниченным контекстом.
5. Ссылки на доказательства и явная маркировка неизвестного.

Это лексический retrieval, не векторные embeddings. RAG с LLM включается только с Gemini. В промпте контекст отделён от инструкций; UI экранирует текст. Неподтверждённые ответы модели всё равно требуют проверки.


## Ограничения и privacy

Локация и история не записываются в localStorage, cookies или базу. GPS обрабатывается в памяти вкладки. Тайловый провайдер получает IP и область карты; Google Fonts получает сетевой запрос. Переход в Google Maps передаёт старт и остановки. Пользователь может выбрать пример района вместо GPS. У локального сервера нет access-логирования.

Время пешком = расстояние по прямой × 1,3 / 4,5 км/ч. Это приближение, а не routing API. Не учитывает переходы, закрытые территории, ветер, снег, очереди и обратный путь. Ночной режим только исключает парки/площадки; не подтверждает безопасность или работу мест. Для аэропорта выводится предупреждение о неучтённой дороге/регистрации. Полный синтаксис opening_hours не вычисляется: исходные часы показываются с оговоркой, без «открыто сейчас». Доступность yes — утверждение сообщества OSM, не наша инспекция.

## Идея продукта

Горожане, семьи и туристы получают короткий выполнимый план вместо длинного списка мест. Отличие: бюджет времени, объяснения и видимый источник в каждой карточке. Бизнес-гипотеза: бесплатные прогулки для жителей, платный B2B-виджет для отелей и городских сервисов; без продажи точной геолокации и скрытой рекламы. Проверка спроса, партнёрства, revenue и пилот пока не проводились.

Дальше: маршруты по пешеходной сети, полноценный opening_hours, обновляемые источники событий, семантические embeddings, казахский язык и оценка качества на размеченных запросах.
